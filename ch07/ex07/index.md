# 問題7.7

## 実装したアルゴリズム

バブルソート(隣り合う2つを比べて、順番が逆なら入れ替える)で `sort(array, compare)` を実装した。

処理の手順は次の通り。

1. 配列の先頭から順に、隣り合う2つ(`array[j]` と `array[j + 1]`)を比べる。
2. `compare(array[j], array[j + 1]) > 0` なら、`array[j]` のほうが後ろに来るべきなので、2つを入れ替える。
3. 1 と 2 を、配列の最後の手前まで(`j` を `0` から `array.length - 2` まで)繰り返す。これを「1回通す」と呼ぶ。1回通すと、そのとき一番後ろに来るべき値が、末尾に移動する。
4. 「1回通す」を、配列の長さ `n` 回繰り返すと、全体が並ぶ。

`[3, 1, 2]` を、昇順に並べる例。

| 回    | 比べる2つ      | 操作             | 配列        |
| ----- | -------------- | ---------------- | ----------- |
| 1回目 | 3 と 1         | 逆なので入れ替え | `[1, 3, 2]` |
| 1回目 | 3 と 2         | 逆なので入れ替え | `[1, 2, 3]` |
| 2回目 | 1 と 2、2 と 3 | どちらも順番通り | `[1, 2, 3]` |
| 3回目 | 1 と 2、2 と 3 | どちらも順番通り | `[1, 2, 3]` |

この実装は、挿入ソートと同じく、引数の配列を直接書き換えて(破壊的に)、その配列を返す。

## 時間計算量

入力の配列長を `n` とすると、時間計算量は **O(n²)** である。

理由は、`for` の2重ループの回数による。

- 外側のループ(`i`)は `n` 回。
- 内側のループ(`j`)は、1回につき `n - 1` 回。
- 内側のループの中で、`compare` による比較が1回ずつ行われる。比較の回数は、合計で `n × (n - 1)` 回になる。
- `n × (n - 1) = n² - n` で、`n` が大きいほど `n²` の項が支配的になる。O-記法では、定数倍と低次の項を無視するので、O(n²) と表せる。

実際に、すでに並んでいる配列で比較回数を数えると、`n × (n - 1)` と一致した。

| `n`   | 比較回数 |
| ----- | -------- |
| 3     | 6        |
| 10    | 90       |
| 100   | 9,900    |
| 1,000 | 999,000  |

`n` が 10 倍になると、比較回数は約 100 倍になる。これは、`n` の2乗に比例する動きである。

この実装では、配列がすでに並んでいても、ループの回数は変わらない。そのため、最悪の場合(逆順)でも、最良の場合(すでに並んでいる)でも、計算量は O(n²) である。

なお、1回通したときに、入れ替えが1度も起きなければ、その時点でループを打ち切る工夫を加えると、すでに並んでいる配列に限って、O(n) まで速くできる。ただし、最悪の場合は、O(n²) のままである。

挿入ソートの時間計算量(O(n²))と、同じオーダーである。
