# 問題7.9

## 実行結果

```js
"𠮷野家"[0]; // => "\ud842" (壊れた文字。画面上は「�」のように表示される)
"👨‍👨‍👧‍👧"[0]; // => "\ud83d" (同じく、壊れた文字)
```

どちらも、見た目の1文字目(`𠮷`、`👨`)にはならず、半分だけの文字が返る。

調べるときに使った式。

```js
"𠮷野家"[1]; // => "\udfb7" (𠮷 の後半)
"𠮷野家"[2]; // => "野"
"𠮷野家".length; // => 4
[..."𠮷野家"].length; // => 3
"𠮷野家".codePointAt(0).toString(16); // => "20bb7"
```

## 結果の説明

JavaScript の文字列は、UTF-16 という形式で、「コードユニット」(16ビット)の並びとして持たれている。`str[i]` と `str.length` は、どちらも「文字」ではなく、**コードユニット**を単位にしている。

Unicode の文字のうち、コードポイントが U+FFFF までの文字(`野`、`家` など)は、コードユニット1つで表せる。一方、U+10000 以上の文字は、コードユニット2つ(サロゲートペア)で表す。

- `𠮷` は U+20BB7 で、`\ud842` と `\udfb7` の2つのコードユニットでできている。`"𠮷野家"[0]` は、そのうちの前半(`\ud842`)だけを返す。後半(`\udfb7`)は、`[1]` に入っている。そのため `"𠮷野家".length` は、3文字なのに 4 になる。
- `👨` は U+1F468 で、これも `\ud83d` と `\udc68` の2つのコードユニットでできている。`"👨‍👨‍👧‍👧"[0]` は、前半(`\ud83d`)だけを返す。

サロゲートペアの片方だけでは、文字として成り立たないので、画面に正しく表示されない。

## 問題7.8で得た絵文字に対する知見

`"👨‍👨‍👧‍👧"` は、見た目は1つの絵文字だが、次の7つのコードポイントでできている。

```
👨 (1f468) + ZWJ (200d) + 👨 (1f468) + ZWJ (200d) + 👧 (1f467) + ZWJ (200d) + 👧 (1f467)
```

ZWJ(ゼロ幅接合子)は、見えない結合用の文字で、前後の絵文字を、1つの絵文字としてつなげて表示させる。さらに、各絵文字は、サロゲートペアなので、コードユニットで数えると 4 × 2 + 3 = 11 になる。

「1文字」の数え方は、単位によって変わる。

| 単位                  | 取り方                          | `"𠮷野家"` | `"👨‍👨‍👧‍👧"` |
| --------------------- | ------------------------------- | ---------- | ------ |
| コードユニット        | `length`、`str[i]`、`split("")` | 4          | 11     |
| コードポイント        | `[...str]`、`for...of`          | 3          | 7      |
| 書記素(見た目の1文字) | `Intl.Segmenter`                | 3          | 1      |

`str[i]` や `split("")` は、コードユニット単位なので、文字を壊す。`[...str]` はサロゲートペアを1つにまとめられるが、ZWJ でつながった絵文字は、7つに分かれてしまう。「見た目の1文字」ごとに扱うには、`Intl.Segmenter` を使う。
