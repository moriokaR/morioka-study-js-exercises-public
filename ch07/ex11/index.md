# 問題7.11

## push の平均時間計算量

問題7.10 の `DynamicSizeArray` の `push` は、空きがあるときと、空きが無いとき(再配置)で、かかる時間が違う。

- **空きがあるとき**: 末尾に1つ書いて、`this.len` を 1 増やすだけなので、O(1)。
- **空きが無いとき(再配置)**: 倍の大きさの配列を作って、今ある `this.len` 個の要素をコピーするので、O(n)。

最悪の1回(再配置が起きる `push`)は O(n) だが、再配置は、配列が倍になるたびにしか起きない。そこで、`push` を `n` 回呼んだときの合計を考えて、`n` で割る(平均を求める)。

### n 回 push したときの、合計の操作回数

1. 末尾に書く操作は、1回の `push` につき1回なので、`n` 回。
2. 再配置は、配列の大きさが倍になるたびに起きるので、約 log₂ n 回。
3. 各再配置でのコピーの回数は、そのときの要素数で、1, 2, 4, 8, ..., 2^(log₂ n) のように倍々になる(この実装では、初期サイズが 4 なので、実際は 4, 8, 16, ... から始まる)。

コピー回数の合計は、等比数列の和の公式で求められる。

```
2^0 + 2^1 + 2^2 + ... + 2^(log₂ n)
  = (2^(log₂ n + 1) - 1) / (2 - 1)
  = 2n - 1
```

つまり、コピー回数の合計は 2n 回未満である。これに、書き込みの `n` 回を足しても、合計は 3n 回未満である。

### 平均

```
(合計の操作回数) / n  <  3n / n  =  3
```

1回あたりの平均は、`n` によらず、一定(3 以下)になる。したがって、`push` の平均時間計算量は **O(1)** である(このような、「何回か続けて呼んだときの平均」の計算量を、償却計算量とも呼ぶ)。

### 実際に数えた結果

`DynamicSizeArray`(初期サイズ 4)に `n` 個を `push` して、再配置のコピー回数を数えた。

| n         | 再配置の回数 | コピー回数の合計 | 2n        | (コピー + 書き込み) / n |
| --------- | ------------ | ---------------- | --------- | ----------------------- |
| 5         | 1            | 4                | 10        | 1.80                    |
| 9         | 2            | 12               | 18        | 2.33                    |
| 100       | 5            | 124              | 200       | 2.24                    |
| 1,000     | 8            | 1,020            | 2,000     | 2.02                    |
| 100,000   | 15           | 131,068          | 200,000   | 2.31                    |
| 1,000,000 | 18           | 1,048,572        | 2,000,000 | 2.05                    |

コピー回数の合計は、いつも 2n 未満で、1回あたりの操作回数は、`n` が大きくなっても、3 未満のまま増えない。

また、1回ごとのコピー回数は、5回目の `push` が 4、9回目が 8、17回目が 16 で、それ以外は 0 だった。再配置のコストは、大きいが、起きる間隔も、倍々に広がっていくため、平均すると小さくなる。

## copyA の時間計算量

```js
function copyA(array) {
  const result = Array(array.length);
  for (let i = 0; i < array.length; i++) {
    result[i] = array[i];
  }
  return result;
}
```

- 長さ `n` の配列を、1回作る。
- ループは `n` 回で、1回につき、読み込み1回と、書き込み1回(どちらも O(1))。

合計は、n × O(1) で、**O(n)**。

## copyB の時間計算量

```js
function copyB(array) {
  const result = [];
  for (const v of array) {
    result.push(v);
  }
  return result;
}
```

- ループは `n` 回で、1回につき、`push` を1回呼ぶ。
- `push` の平均時間計算量は O(1)。

合計は、n × O(1) で、**O(n)**。

「`push` は、再配置が起きると O(n) かかるので、n 回で O(n²) ではないか」と考えるのは、間違い。最悪の1回が O(n) でも、再配置は、倍々の間隔でしか起きないので、`n` 回の合計は O(n) に収まる(上の、コピー回数の合計 < 2n の通り)。

## NOTE への回答

> copyB よりも copyA の方が効率的に見えるが計算量の観点ではどうだろうか

計算量の観点では、**どちらも O(n)** で、オーダーは同じ。

`copyA` は、最初に必要な大きさの配列を確保するので、再配置のコピーが無い。`copyB` は、再配置のコピー(合計 2n 回未満)が、余分にかかる。そのため、`copyA` のほうが、定数倍(かかる時間の係数)は小さい。ただし、`n` が大きくなったときの増え方は、どちらも `n` に比例する。O-記法では、定数倍は無視するので、同じ O(n) として扱う。
